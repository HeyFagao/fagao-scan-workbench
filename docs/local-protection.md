# 本机保护与恢复

官网继续决定账号、设备和使用期限，榜单与分析功能继续在用户电脑运行。本轮在原有授权及榜单包加密分发之外，增加设备凭据密封、关键模块的本机封装和官方安装完整性检查。具体系统与发布版本的实测结果见[验收记录](acceptance.md)。

## 保护范围

| 层次 | 保护对象与作用 | 实际边界 |
| --- | --- | --- |
| 官网授权与加密分发 | 官网核验账号及设备，按短时许可提供榜单包密钥；新任务资格以官网为准 | 已获准显示在本机的数据仍可被本机使用者观察；公开直采来源也继续在本机读取 |
| 本机凭据密封 | 保护工作台专用设备凭据及本机封装密钥，降低直接复制状态文件的风险 | 不创建会员资格；有权使用当前系统账号的进程仍可能调用系统解封能力 |
| 关键模块封装 | 官方安装中的 `membership.py`、`runtime.py`、`network.py` 以每安装随机密钥封装为认证密文，加载时核验并还原执行 | 公开仓库仍提供源码；只提高本机副本的静态扫描与复制成本，不保证阻止 REA 或其他逆向工具 |
| 安装完整性 | 启动、CLI 与服务复用前核验官方程序文件；损坏后按同一固定源码和 SHA-256 重新准备 | 当前本地清单不是独立的发布签名，也不能证明刻意修改过整个客户端的人仍执行了检查 |

数据库、已保存榜单、正文、收藏、报告和用户配置保持原格式，不进行旧库批量加密。内部维护声明保留在源码、封装后的加载文件和维护文档，会员页面不显示反破解提示。

## 系统安全存储

- Windows 使用当前系统用户范围的 DPAPI，不使用“本机任意用户均可解封”的机器范围选项。
- macOS 使用系统钥匙串，应用记录绑定稳定资料根目录和用途，不随每次发行目录变化。
- Linux 使用权限受限的本机密钥文件与认证密文。这层依赖系统文件权限，不等同于硬件隔离或系统钥匙串。

Windows 或 macOS 的原生安全存储失败时，不静默改成明文或本机文件密钥。旧明文设备凭据在首次需要联网续领前，先完成密封写入与安全回读，再原子替换，随后仍需官网核验使用资格。构造对象或仅读本地状态不自动迁移；密封失败时保留原状态、停止该次网络续领，并报告系统存储故障。已有密文无法解封时不重新生成密钥覆盖。

接口依据：[Microsoft DPAPI](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata) · [Apple Keychain Services](https://developer.apple.com/documentation/security/keychain-services)。这些接口的具体可用性仍以当前电脑与系统账号为准。

## 正常故障处理

| 状态 | 维护助手的处理 |
| --- | --- |
| 会员有效但服务拒绝 | 正常联网核对官网权益、退款及设备状态；不能修改本机到期时间或伪造许可 |
| 系统钥匙串锁定 | 保留原文件，请本人解锁系统钥匙串后重试 |
| 本机设备凭据丢失、属于其他系统用户或完整性失败 | 保留资料与原状态；显式重新连接时先测试系统存储，再原样私有备份旧状态，随后正常官网授权 |
| 代码封装密钥锁定或系统存储暂时不可用 | 延后启动，先解锁或恢复系统存储，不删除程序或资料 |
| 关键模块密文、认证标签、原始摘要不匹配，或代码封装密钥丢失 | 返回安装完整性/修复状态，停止使用该程序副本，从可信固定归档恢复相同版本 |
| 官网撤销、退款阻断或使用期到期 | 按官网结果停止新任务，已经保存的资料按历史权限读取，不用安装修复替代权益判断 |

代码封装的清单位于该程序发行目录的 `.fagao-code-seal.json`，与可信安装文件清单一起核验。这是每次本机安装的私有产物，不进入源码 ZIP 或 GitHub。封装密钥通过上述安全存储保护并绑定稳定资料根目录。不要手工删改清单、密文或密钥来排查；它们损坏时保留现场，由维护助手处理。

## 正式命令行入口

WorkBuddy 使用 `current.json` 中记录的解释器，通过参数数组调用安装根目录中的固定入口：

```text
PYTHON_ABSOLUTE_PATH -I -B OPEN_CLI_ABSOLUTE_PATH --session SESSION_ID COMMAND [COMMAND_ARGUMENTS]
```

`OPEN_CLI_ABSOLUTE_PATH` 为该安装根目录内 `open-cli.py` 的绝对路径；其他大写项由助手替换为真实解释器、当前对话 ID 与操作。Windows 使用同一参数顺序，路径作为独立参数传递。入口固定读取当前版本及原资料目录，在加入业务模块路径前核验程序；不接受 `--data-dir`、`--install-root` 等覆盖。旧 `python -m fagao` 保留源码开发兼容，不能称为这条受控启动链的安全边界。

## 安装修复、换机与降级

官方安装完整性失败后，安装助手沿用原安装命令，取得原回执中固定提交、相同 SHA-256 的可信归档，先验证新的暂存程序。无需添加修复参数。若该程序仍在运行，安装器返回 `restart_required` 与继续操作信息，保持当前指针不变；精确停止对应工作台后重跑原命令，不按进程名批量结束程序。

修复将原程序保留在安装根目录的 `quarantine/<源码提交>-<唯一编号>/`，再原子替换该程序版本；完成结果为 `repair.status=repaired`。账号库、`.membership/`、正文、报告及 WorkBuddy 项目规则不被覆盖。开发者 `--source-dir` 目录损坏仍拒绝自动修复。新程序启动失败时，在确认该版本无运行进程后可恢复旧目录；仍有进程占用时保留备份和恢复信息，不强制删除。

完整个人备份可能含账号资料与本机密文，应妥善保存；复制目录到另一电脑不保证能够解封。更换电脑时使用正常官网连接流程，原资料保留，三台设备规则继续生效。资料根目录移动会改变本机密封绑定，不能只改路径后假定凭据仍可用。

旧版客户端不能读取新密封凭据。需要降级时，先在支持密封的新版本正常退出，再让旧版通过官网重新连接；不要把密文改回明文。保持同一新版本的可信程序修复则应保留原密封凭据和账号资料。

这里没有加入重度反调试、扫描用户其他应用、结束无关进程或修改系统安全策略。后续若调整保护方式，仍需先验证到期只读、旧资料、换号、取消、系统存储故障及恢复流程。[会员与资料规则](membership.md) · [内部维护声明](ai-maintenance-boundary.md)
